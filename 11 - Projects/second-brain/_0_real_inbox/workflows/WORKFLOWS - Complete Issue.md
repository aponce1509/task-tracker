# [[WORKFLOWS - Complete Issue]]

> [!summary]
> Closing an issue requires cleaning up code/thought debt, documenting lessons, and capturing spin-off problems.

When an Issue is resolved and ready to close:
1. **Finalise the Journal:** Ensure your scratchpad/journal entries contain at least 1-2 final technical comments, logs, or links explaining *how* the issue was ultimately fixed.
2. **Audit Technical Debt & Bugs:** 
	- Did you use a quick fix or temporary hack? 
	- Did this solution reveal a new bug or open problem? 
	- If yes, instantly create a new [[Issues]] ir [[Project Contexts]] note for it with the tag it `#technical-debt` or just add the tag in some note.
3. **Draft Missing Knowledge:** If you learned something unique or solved a rare problem, create a new atomic note (`#_capture`) linking to this solution so your future self has it documented.
4. **Merge & Archive:** Check off the final issue steps, update the metadata status to completed, and log a reference link to this issue inside your main Project note's history log.
5. If the solution is worth to mention create a [[Solutions]] note.
