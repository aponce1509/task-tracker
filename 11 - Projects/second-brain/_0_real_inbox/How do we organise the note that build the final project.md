# [[How do we organise the note that build the final project]]

> [!Important] Implementation Note Any note that talks about the final project
> solution/implementation should be tagged by `core_component`

A product, implementation or any other type of project is build by many
intermediate pieces that will be in your [[Final Project Document]].

## Writing this design intermediate note

You have a base knowledge build during your lifetime, that may no be present
here in your second brain. You have memories before this system was born.

So when you are designing a product or a solution you may use this resources but
no notes can be use and you don't want to waste time creating the theory notes
and then your solution.

Ideally your solution is build alone with existing note but this may not be the
case.

Let's define some examples:

- Implementing CODE in your Second Brain
- How to implement a clustering workflow for the NMD model
  - You may create new notes about categorical data, clustering models you don't know
  - But there are thing you know, like pca or kmeans that you won't detail.

## CODE - Example

Context: long time ago you read a book an saw plenty of books about this topic
so it became a [[Foundation Knowledge]] for you.

Now I'm defining how we are implementing my second brain. So I write a
[[Map of Contents]] for what do I understand by CODE. I had some doubts, but I
remembered the book and where to look for solve this doubts.

So I wrote the MoC and I wrote my implementation of CODE and how it relates to
my implementation.

Here the purist workflow should have been:

1. You have your notes about this. Maybe a CODE Methodology literature review
   that links all the notes about code. With examples, annotations, opinions.
2. The you define you implementation with all the ideas.
3. Then your task is to distill this implementation until you integrates CODE to
   your workflow. So you may have ended with the notes like:
   4. How we apply CODE: Linking to the external info and talking about your real implementation
   5. Organising your notes efficiently: this note talks about your own implementation
