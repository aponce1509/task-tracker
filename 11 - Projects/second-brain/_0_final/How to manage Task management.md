# [[How to manage Task management]]

> [!abstract] The first decision on task management, now superseded
> - Options: `wip` for incomplete notes, one central note of issues, `- [ ]` with the Tasks plugin.
> - Decision then: one central note of issues, and `wip` on every incomplete note.
> - Now: one note per issue ([[The Issue System]]); the `wip` rule stays.

## Options

- `wip` status for incomplete notes.
- One central note where I put the issues.
- `- [ ]` checkboxes and the Tasks plugin.

## WIP

Whatever the choice, every incomplete note gets `status: wip`. It is completed when I use it again, or it becomes a task.

> [!important]
> - Do not confuse `wip` with `capture`. A capture without distillation is only a capture (`maturity: capture`). A `wip` note is a note that I started and can improve or distill (`status: wip`). The two axes: [[The CODE system]].

## Central note

The decision then: the most comfortable option. I keep the issues note open, with an inline base of the `wip` notes. Separate notes for independent issues already had value: [[This is really a Task]].

## What changed

The central note became one note per issue in `08 - Issues/`, with bases per project: [[The Issue System]] · [[Task Management]].
