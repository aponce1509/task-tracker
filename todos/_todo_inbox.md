# Inbox

## Second Brain Organization

1.  Tienes que pensar como hacer notas de código pero que sea solo código, es
    decir como puedes estructurar un repo para poder usarlo para incluir cosas
    útiles de código.

    - Vas a tener proyectos donde puede que quieras usar cosas o patrones
      interesantes. Esto debe vivir en el proyecto no en el código
    - Cuando estas aprendiendo algo de código lo suyo es que lo pongas como
      código y hagas pruebas sobre ese código
      - Cada script una idea usando nombres interesante, todos los script tienen
        la misma forma (if main de manera que lo relevante esta ahi). Creas un
        Readme a modo de indice que explique el contenido de cada carpeta
      - Usar los test como cuaderno de notas: basado en TDD.
      - Jupyter Notebooks para python y R

2.  En OneNote usamos los tags para marcar los outputs:

    - Códigos
    - Atómicas
    - Importante
    - Questions

    Lo tenga más de un tag. Una nota sin tag debería significar que no hay nada
    relevante

3.  Hay dos tipos de tags: limpieza y revision
4.  Hay notas predefinidas
    - Nota del día: tareas que hacer y Hemingway
    - Lista de referencias, puede que sea interesante usar un tag: URL
