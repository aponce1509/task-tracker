# New Work - New Life

The objetive is to deliver good quality results: Code, Models, Ideas. That can
be reused in the future and that are accesible.

- ==THE ONLY MUST: MIMIC THEIR WAY OF WORKING EVEN IF YOU DON'T AGREE. THEY WANT
  RESULTS WITH THEIR OWN STANDARDS==.
- ==Always think in tasks==, which must be jira tasks.
- ==Write always good quality code.== Spend time here and try to make the things
  cleaner but following the their "how's to", at most suggest some changes, step
  by step <https://youtube.com/shorts/ftUyIza7S-k?si=h8IkZtzdt_G6xBxl>.
- Follow a completion task list
  - The initial requirement is done.
    - Put yourself in the client perspective → improve if needed
  - Test are written
  - The code is documented, has a high locality.
  - The code is pushed to git
  - Notes are moved. IF THERE ARE NO NOTES make some (5 min at most if not
    needed).
  - (Any added by them)
  - ... To be completed after working there (keep in mind the initial objetive).
- No todo es programar, de hecho diría que es lo menos importante. En orden de
  importancia
  - Resultados
  - Demostrar lo que haces
  - Documentación
  - Código
- Have clear side projects related with your work the are mandatory, you should
  prioritize them over personal ones.

There are different types of tasks:

- CODE Task
- Documentation tasks → Task that has as objetive learning something
- Automation task → Task in order to improve the team productivity
- Support Tasks → Help someone or fix something
